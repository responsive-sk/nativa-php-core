# A password minimum typed in three files, two public writes with no throttle of their own, a CSRF gate that read only the token, and an audit script that killed itself

**Date:** 2026-10-16 00:36
**Files:** modules/Security/Domain/PasswordPolicy.php (new), modules/Security/Domain/LocalClient.php (new), modules/Users/Application/Services/AuthService.php, modules/Users/Application/Services/PasswordResetService.php, modules/Users/Interfaces/HTTP/Actions/Auth/RegisterAction.php, modules/Users/Interfaces/HTTP/Actions/Auth/PasswordResetRequestAction.php, modules/Users/Interfaces/HTTP/Actions/Auth/ThrottledResponse.php (new), modules/Users/Interfaces/HTTP/AuthServices.php, modules/Cardboard/Interfaces/HTTP/Actions/UsersAction.php, modules/Comments/Application/Services/CommentsService.php, src/Modules/Core/Infrastructure/Http/Request.php, src/Modules/Core/Interfaces/HTTP/Middleware/CsrfMiddleware.php, tests/Http/CsrfMiddlewareTest.php (new), module tests, lekalo/modules/users/policies.yaml, .env.example, bin/build/kernel-divergence.txt, docs/kernel-status.md
**Severity:** medium (findings #3, #4, #6), low (finding #7), tooling (finding #8)

## Problem

Five audit findings, four of them remediable code:

1. **#3** the password minimum was `8` in three places — `AuthService::register()`,
   `PasswordResetService::reset()` and the admin user form
   (`Cardboard\…\UsersAction::validate()`), with the message
   `'Password must be at least 8 characters.'` retyped at each — while the
   repo's own checklist asks for the ASVS 2.1.1 baseline of 12. Four copies of
   one policy is four chances for the admin form to keep accepting what
   registration refuses.
2. **#4** `POST /register` had no limit of its own; the only bound was the global
   60/min/IP middleware.
3. **#6** `POST /forgot-password` had none either: each request DELETEs +
   INSERTs a token row, so a distinct address per request grows the table (and,
   in development, appends a log line) without bound.
4. **#7** `CsrfMiddleware` validated the token and nothing else, so a cross-site
   POST carrying a token — leaked in a referrer, scraped from a cached page,
   replayed — was accepted.
5. **#8** `.agents/skills/aif-security-checklist/scripts/audit.sh` exited **1**
   after its first section, with no Summary and empty stderr, on a clean tree.

## Root Cause

**The findings are four instances of one habit: a rule written where it is
needed, never owned.** The password minimum was copied to each new form instead
of asked from a single place; the throttle was added to `login()` (which had an
observable failure mode: credential stuffing) and not to `register()` or
`/forgot-password` (whose failure modes are quieter — a table that grows, a
mailbox that fills); the CSRF gate implemented the token, which is what the
class is named after, and stopped there. None of these are hard bugs; each is a
control that exists next to the thing it protects rather than in one place that
all of them ask.

**`audit.sh`'s root cause is a bash idiom, and the generic form is worth
keeping:** `((ISSUES++))` is an arithmetic *command*, and a command whose result
is 0 — the value before the increment — exits with status 1. Under `set -e` the
first branch entered killed the script, silently, because `set -e` does not
print. The script's own exit code looked like a finding.

**And the audit script's second defect explains why nobody noticed the first:**
its secrets regex matched any `key = …` assignment, which reported 20 benign
lines in this tree. A tool whose output is mostly noise is a tool nobody reads,
including its crash.

## Solution

- **#3** `Modules\Security\Domain\PasswordPolicy` owns `MIN_LENGTH = 12` plus
  `minRule()` / `tooShortMessage()`; the three call sites compose them and the
  pinned messages derive from the policy. `Security` is the owner because
  `Cardboard`'s closure is `Outbox, Security, Settings, Validation` — `Users` is
  not in it — so no new coupling edge is paid (`KernelCouplingTest` stays empty).
  `lekalo/modules/users/policies.yaml` says 12 and now covers the admin edit
  command (`users.update_user`); `lekalo lock --check` does not move (the lock
  covers the resolver, not descriptions).
- **#4/#6** `AuthService::register()` gained `$ip` and 5 accounts / 3600 s;
  `PasswordResetService::requestReset()` gained `$ip` and returns
  `array{ok, retryAfter}`, limited 5/900 s per caller **and** 3/3600 s per target
  — asked BEFORE the token row is rewritten, so a refusal cannot invalidate a
  link the reader already holds. Both answer 429 + `Retry-After` through one
  `ThrottledResponse`, with no `Location` header (a redirect discards the body).
  The registration limit counts accounts CREATED, not attempts: after
  validation, before the insert.
- **#4/#6 loopback** `Modules\Security\Domain\LocalClient::isLoopback()` is the
  one owner of "the local developer is not a spammer"; `CommentsService`'s
  private list folded into it. Core keeps its own copy (Core may not name a
  module).
- **#7** `Request::isSameOrigin(string $url)` compares a URL's host against the
  request Host through the same `trustedHosts()`/`isTrustedHost()` guard
  `absoluteUrl()` uses; `CsrfMiddleware` calls it with `Origin`, falling back to
  `Referer`, **after** the token check (so a tokenless request is refused exactly
  as before), and leaves a request carrying neither header to the token alone.
- **#8** four `ISSUES=$((ISSUES + 1))`, and the secrets pattern requires a quoted
  literal of 8+ characters (plus an explicit `apiKey` alternative — see
  Prevention). Before: exit 1, one section. After: exit 0, six sections.

Left alone on purpose, and written down: no `/reset-password` limiter (a 256-bit
token is not brute-forcible; the global middleware bounds the rate), and no code
change for the same-host untrusted-proxy case where `REMOTE_ADDR` is always
`127.0.0.1` (that is configuration — `.env.example` now says so next to
`TRUSTED_PROXIES`).

## Verification

Live HTTP on a fresh `php -S` with a real session and a real token from
`GET /register`: cross-site `Origin` **with a valid token** → 403
`Cross-site request rejected`; same-origin `Origin` + token → 200; no token +
cross-site → 403 `CSRF token validation failed` (token decided first);
cross-site `Referer` alone → 403; neither header + token → 200; `Origin: null`
→ 403; `storage/data/users.db` unchanged.

Live throttle probe through the real actions with a synthetic non-loopback
`REMOTE_ADDR` (temp DBs): register 5 → 302 then 6th → 429 `Retry-After: 3599`
with exactly 5 rows stored; reset per target from four different callers 3 → 200
then 4th → 429 `Retry-After: 3600`; reset per caller 5 → 200 then 6th → 429
`Retry-After: 900`; loopback 7 of 7 accepted.

Five mutation checks, each reverted: hardcoding `min:8` in `register()` fails
`AuthServiceTest`; `LocalClient::isLoopback()` → `false` fails two files;
registration limiter → `true` fails the 5-per-hour case; `FORGOT_EMAIL_LIMIT = 30`
fails the per-target case; disabling the CSRF cross-check fails the five
cross-site/`null` cases while the same-origin, `Referer`, absent-header and token
cases stay green. Full suite 310 tests / 1296 assertions / 1 skip; phpstan level 9
clean; cs-fixer clean on every touched file; `make lint`, `make lekalo-check`,
`make extract-check` (222 identical, 66 recorded divergences) green.

## Prevention

- **One owner per number, in the module both consumers already depend on.** The
  cheapest place for a shared policy is where the dependency edge already is:
  here both `Users` and `Cardboard` depend on `Security`, so the constant cost no
  new coupling. Check the closure before choosing the home, not after.
- **A throttle must count the thing being abused.** Accounts created, not form
  posts, keeps an honest reader who mistypes a password five times out of a
  lockout; a per-target key alongside the per-caller one is what stops a public
  "send me a link" endpoint being an amplifier aimed at somebody else's inbox.
- **Refuse with a status and a retry time, and without a `Location`.** A 429 with
  no `Retry-After` is a dead end for a client that speaks HTTP; a 429 that also
  redirects has its body thrown away, so the client never reads why.
- **A new cross-check must be ordered so it cannot change an existing refusal.**
  Token first, origin second: every pre-existing probe keeps its exact status and
  message, and only the case that used to be accepted (a valid token from
  elsewhere) changes.
- **Absent evidence is not evidence of forgery.** `curl`, a server-to-server
  call, an old same-origin form and a proxy that strips both headers send no
  `Origin`/`Referer`; a cross-check that refuses them gets reverted the day it
  breaks an integration. Fail closed only on values that ARE present and name
  another host (`null`, malformed, a sibling subdomain).
- **`set -e` turns `((i++))` into a silent exit.** Use `i=$((i + 1))` in any
  script that must reach its summary — and when a tool "fails" with no output,
  suspect the shell, not the check.
- **Fix the noise before trusting the signal.** A greppable audit that reports 20
  benign assignments is why its own crash went unnoticed; tightening the pattern
  to quoted literals is what made the script's output worth reading. When
  tightening a regex, measure both directions — `-i` was the obvious way to catch
  camelCase `$apiKey` and it re-flagged three `INVALID_TOKEN = 'passwords.token'`
  constants in `vendor/`, so the spelling went into the alternation instead.
- **A vendored fix is local on purpose — say so.** `.agents/` is hash-managed and
  gitignored; the fix is recorded in `docs/kernel-status.md §9` and the installed
  hash is deliberately NOT rewritten, so a future `$aif` may flag or re-install
  the file. Recording the consequence is what makes the local fix honest.
