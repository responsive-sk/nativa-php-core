- **Location:** `src/Modules/Core/Infrastructure/Http/Request.php:112-145` (getClientIp) + `src/Modules/Core/Interfaces/HTTP/Middleware/RateLimitMiddleware.php`
- **Description:** `X-Forwarded-For` / `X-Real-IP` boli akceptované bez overenia, či je peer trusted proxy. Útočník mohol každý request poslať s inou XFF hodnotou a dostať samostatný rate-limit bucket → neobmedzené brute-force pokusy na login/register/reset.
- **Oprava (implementovaná):** `Request::getClientIp()` rešpektuje forwarded hlavičky len keď je `REMOTE_ADDR` v `TRUSTED_PROXIES` (IP/CIDR, `.env.example`); inak vracia `REMOTE_ADDR`. Regresné testy v `tests/Unit/RequestTest.php` + commit `3358327`.
- **Verification (live, 2026-08-07):** ```bash # 6 loginov s rôznymi XFF, rovnaký email — bucket musí byť zdieľaný for i in 1 2 3 4 5 6; do curl -s -X POST http://127.0.0.1:8000/login \ -H "X-Forwarded-For: 203.0.113.$i" -d 'email=timing@example.test&password=wrong&_token=...' | grep -q 'Too many' && echo "attempt $i: RATE LIMITED"; done # attempt 1-5: invalid credentials | attempt 6: RATE LIMITED ✅ ``` - E-1: 6. pokus → „Too many failed attempts" (`attempt 6: RATE LIMITED`) — bucket zdieľaný napriek rôznym XFF. `confidence: high`, `status: fixed` → overené. - P-1: request → XFF hlavička → `getClientIp()` vracia `REMOTE_ADDR` (127.0.0.1) → kľúč `login:127.0.0.1:email` zdieľaný → 6. pokus zamietnutý. ### F-2 [Timing side-channel — user enumeration na logine] — FIXED - **Severity:** Low
- **Location:** `src/Modules/Users/Application/Services/AuthService.php:88-106` (`login()`), route `/login`
- **Description:** Pre existujúci email beží `password_verify()` (ARGON2ID, ~150 ms); pre neexistujúci email funkcia vrátila okamžite (~10 ms). Odpovede boli textovo identické („Invalid credentials."), ale **časová odpoveď** umožňovala rozlíšiť existujúci email od neexistujúceho — user enumeration vektor pre phishing/ďalšie útoky.
- **Impact:** Útočník mohol cez meranie latencie enumerovať registrované emaily (príprava phishingu, credential-stuffing cielenie).
- **Reproduction (pred opravou):** ```bash # existujúci email time curl -s -X POST http://127.0.0.1:8000/login -d 'email=admin@example.test&password=wrongpass123&_token=...' # ~152-156 ms # neexistujúci email time curl -s -X POST http://127.0.0.1:8000/login -d 'email=zzz-nonexistent@example.test&password=wrongpass123&_token=...' # ~10-11 ms ``` - E-1: 3 merania: known `156/152/156 ms` vs unknown `11/10/10 ms` — ~15× rozdiel, stabilný. `source_ref: src/Modules/Users/Application/Services/AuthService.php:92-101`, `status: confirmed`. - P-1: login POST → email nenájdený → `recordLoginAttempt` + okamžitý return (žiadny hash verify) → rýchla odpoveď. Existujúci email → `password_verify()` (ARGON2ID) → pomalá odpoveď.
- **Oprava (implementovaná, 2026-08-07):** vetva pre neexistujúci/inaktívny účet teraz spúšťa **dummy `verify()`** proti konštante `DUMMY_PASSWORD_HASH` (precomputed ARGON2ID hash z náhodných bytov, plaintext nikde nezaznamenaný → žiadne heslo ho nikdy nematchne; výsledok verify je zahodený), takže časová krivka je zjednotená s reálnou kontrolou: ```php // AuthService::login() private const string DUMMY_PASSWORD_HASH = '$argon2id$v=19$m=65536,t=4,p=1$aXZOQ1Brc2tLSGJQZXBjbw$O2tMeAeT9JZDs+5i5Spi6Lb2Xc9bV/RezKjqfsxPGkE'; // ... if (null === $user || !$user->isActive()) { $this->hasher->verify($password, self::DUMMY_PASSWORD_HASH); // výsledok zahodený $this->limiter->recordLoginAttempt($email, $ip); return ['user' => null, 'errors' => ['Invalid credentials.']]; } ``` Poznámka: dummy hash je generovaný s defaultnými ARGON2ID options — ak `PasswordHasher` niekedy zvýši `memory_cost`/`time_cost`, treba hash regenerovať s rovnakými options (komentár pri konštante).
- **Regresný test:** `tests/Integration/UsersModuleTest.php` — `testUnknownEmailLoginStillRunsPasswordVerify()` overuje, že `verify()` je zavolaný aspoň raz aj pre neexistujúci email (mock `PasswordHasher` s `expects(once())`).
- **Verification of fix:** zopakovať merania — rozdiel known/unknown musí klesnúť na < 5 ms (hluk siete). ### F-3 [.env: APP_ENV=production + APP_DEBUG=true] — FIXED - **Severity:** Low
- **Location:** `.env` (repo root)
- **Description:** `.env` má `APP_ENV=production` ale `APP_DEBUG=true`. Dôsledky: (1) **HSTS sa nikdy neposiela** — `SecurityHeadersMiddleware::addSecurityHeaders()` posielal HSTS len keď `APP_DEBUG=false` (`source_ref: .../SecurityHeadersMiddleware.php:89-92`); (2) debug error pages (stack trace) by mohli byť aktívne v produkčnom režime.
- **Impact:** Chýbajúci HSTS na HTTPS nasadení (SSL-strip risk); potenciálny únik detailov chýb ak by sa taký `.env` nasadil do produkcie.
- **Oprava (implementovaná, 2026-08-07):** - HSTS gate presunutý z `!APP_DEBUG` na `APP_ENV === 'production'` (`SecurityHeadersMiddleware`), takže debug režim už HSTS nevypína a HSTS sa posiela presne v produkcii. - Lokálny `.env` nastavený na `APP_ENV=development` (dev box); `bin/build/build-dist.sh` už nastavuje `production`+`APP_DEBUG=false` správne. ### F-4 [Hlavička X-Powered-By] — FIXED - **Severity:** Low
- **Location:** server config / PHP ini (`expose_php`)
- **Description:** odpoveď obsahovala `X-Powered-By: PHP/8.5.8` — presná verzia PHP zjednodušuje cielenie na známe CVE.
- **Oprava (implementovaná, 2026-08-07):** `header_remove('X-Powered-By')` v `src/init.php` (server header hardening, pred akýmkoľvek outputom) — overené, že odstráni hlavičku aj na PHP built-in dev serveri. Produkčné servery by mali navyše `expose_php = Off` v php.ini (defense-in-depth). ### F-5 [Session cookie bez Secure flag] — FIXED - **Severity:** Low
- **Location:** `.env` (`SESSION_SECURE=false`) / `config/session.php` / `AuthService` (remember-me cookie)
- **Description:** `Set-Cookie: nativa_startah=...; path=/; HttpOnly; SameSite=Lax` — chýbal `Secure`. Na čistom HTTP (dev) je to OK, ale ak by rovnaký config šiel na HTTPS produkciu, cookie by sa posielala aj po HTTP.
- **Oprava (implementovaná, 2026-08-07):** auto-detekcia HTTPS — nový `Env::isHttps()` (priame signály `HTTPS`/`REQUEST_SCHEME`/`SERVER_PORT=443`; **forwarded hlavičky sa ignorujú** — spoofovateľné, rovnaká disciplína ako F-1). `config/session.php` nastavuje `session.cookie_secure` z auto-detekcie, ak nie je `SESSION_SECURE` explicitne nastavené (prázdna hodnota = auto). Remember-me cookie v `AuthService` používa rovnaký flag. Jednotkové testy `tests/Unit/EnvTest.php`. ### F-6 [/.htaccess servírovaný dev serverom] — FIXED - **Severity:** Info
- **Location:** `public/.htaccess` (obsluha `php -S`)
- **Description:** PHP built-in dev server servíroval `/.htaccess` ako statický súbor (HTTP 200). Obsah je neškodný (rewrite + security headers + caching konfigurácia pre Apache), žiadne tajomstvá. V produkcii (Apache/nginx) sa súbor nikdy neposiela — Apache ho interpretuje, nginx ho ignoruje.
- **Oprava (implementovaná, 2026-08-07):** nový router script `bin/dev/dev-server-router.php` pripojený do `bin/cms serve` — vracia **404 pre dotfiles** (`/.htaccess`, `/.env`, ...) a blokuje `..` traversal segmenty (lexikálne, takže in-docroot symlinky na zdieľané build adresáre fungujú). V produkcii naďalej platí `public/.htaccess` (`<FilesMatch "^\."> Require all denied`) pre Apache; pre nginx odporúčam `location ~ /\.` deny. ## 5.
