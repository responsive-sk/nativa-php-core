# Template Surfaces Map

Every screen in the kit, where its markup lives and what renders it. Conventions:
`docs/admin-templates.md` (ViewRenderer details) and `docs/theme-layout.md` (theme
section-directory layout).

## The three stacks

| Stack | Mechanism | Markup home | Guard |
|-------|-----------|-------------|-------|
| Public frontend | `FrontendLayout` shell + `ThemeModule` implementations | `src/Themes/*/` (PHP classes) | `ThemeFileSizeTest`, `ThemeOwnershipTest`, `CriticalCssByteParityTest` |
| Admin (`/mark`) | `AdminLayout`/`CompactLayout` shells + `ViewRenderer::render()` includes | `src/Modules/*/Interfaces/HTTP/templates/*.phtml` | `TemplateHygieneTest` |
| Auth | `AuthTemplate::render()` (self-contained card layout, `--auth-*` tokens) | `src/Modules/Users/Interfaces/HTTP/AuthTemplate.php` | `AuthTemplateTest` |

Shared Core view helpers (used by all three): `Modules\Core\Application\Services\View\`
— `ViewRenderer`, `InlineCss::files()`, `InlineJs::file()`. Client-side assets live
only in the theme packages under `Frontend/packages/<theme>/` (Vite → `public/dist/<theme>/`).

## 1. Public frontend — theme modules

Shell: `FrontendLayout::render()` is a theme-agnostic head/document connector —
it builds `ShellContext` (menus, locale data, auth state), resolves the active
theme through `ThemeKernel::for($theme)` and delegates body chrome
(header/footer/page-wrap) and assets to the resolved `Themes\ThemeModule`.
Actions build the per-surface `PageContext` payload and call ONE surface method
on the module (`homepage()`, `blogIndex()`, `blogSearch()`, `blogArticle()`,
`blogTags()`, `blogCategories()`, `authorProfile()`) — the kernel owns data,
the theme owns ALL markup (ADR-0003, guard `ThemeOwnershipTest`).

| Surface | Route | Action | ThemeModule method |
|---------|-------|--------|-----------------|
| Homepage | `/` | `Core\...\HomepageAction` | `homepage()` |
| Blog index (+ `?q=` search) | `/blog` | `Blog\...\BlogIndexAction` | `blogIndex()` / `blogSearch()` |
| Article | `/blog/{slug}` | `Blog\...\BlogArticleAction` | `blogArticle()` — plus the owner-edit affordance (`PageContext::$editUrl` + `$editLabel`) and the inline Markdown editor (`PageContext::$inlineEditHtml`), both resolved kernel-side via the same `ArticleWriteGuard::owns()` answer; empty strings for every other visitor |
| Inline body save | `POST /blog/{slug}/inline` | `Blog\...\BlogInlineEditAction` | — (no browse route; 302 to `?saved=1`, or an HTMX notice fragment). Second public write path into the same `.md` file `/mark` writes: goes through the SAME `ArticleWriteGuard::save()`, saves ONLY the body (front matter is re-read from the file and passed through), 403 on refusal with NO `Location` header, 400 for a non-string body. Markup: `Blog\...\BlogInlineEditor`, module-owned and prefixed per theme — the same `CommentSection` contract |
| Tags cloud / tag list | `/blog/tags[/{tag}]` | `Blog\...\BlogTagsAction` | `blogTags()` |
| Category grid / category list | `/blog/categories[/{cat}]` | `Blog\...\BlogCategoriesAction` | `blogCategories()` |
| Author profile | `/authors/{slug}` | `Blog\...\AuthorProfileAction` | `authorProfile()` |
| CMS page | `/{page}` | `Pages\...\PageViewAction` | — (own markup, `FrontendLayout` directly). Per-locale slugs via `translation:` front matter (each locale's own slug in canonical/hreflang); previous slugs answer 301 from machine-managed `aliases:` (query preserved) |
| Embedded form block | — (no browse route) | `Forms\...\FormBlockRenderer`, expanded by `FormShortcodeBlock` while Pages/Blog render markdown | — (module-owned markup, `FrontendLayout` directly). Rendered under the active theme's prefix (`st-form`/`er-form`/`ms-form`/`mag-form`) — the same `CommentSection` contract; there is deliberately NO `ThemeModule` surface. CSS: `Frontend/packages/<theme>/…/form.css`, generated by `bin/generate/generate-form-css.mjs` |
| Author Markdown editor | — (no route; enhances the article page's inline editor) | `Frontend/packages/<theme>/src/inline-editor.ts`, applied over the textarea `Blog\…\BlogInlineEditor` renders | — (client-side only, module-independent). Formatting toolbar + live preview, built only when the `<details>` opens. The `<textarea name="body">` stays the field that submits, so no-JS, Chrome 70 and mobile all keep working. Escape-first, with the same URL allowlist as `MarkdownRenderer`. Duplicated byte-for-byte per package (`FrontendPackageParityTest`). Opening the disclosure promotes the same `<details>` to a fixed full-viewport sheet (`src/inline-editor-fullscreen.ts`, restyled never moved; Escape closes, body scroll locks, unsaved edits prompt first). Browser checks: `bin/checks/inline-editor-check.mjs` (60 assertions per theme) and `bin/checks/nojs-check.mjs` (the no-JS fallback) |

Theme directories (the wired themes — starter public default, moonshine admin +
public, erik, magazine, basic and jednotka public, selectable via the `theme`
setting; there is no fixed count, a theme is a module):

```
src/Themes/
├── ThemeModule.php   # the theme-module contract (identity + assets + chrome + surfaces)
├── starter/   StarterTheme.php (ThemeModule impl) + Chrome/{Nav,FooterNav,LocaleSwitcher,ThemeToggle,UserLink} + Sections/{Support,Hero,BlogIndex,Widgets,Chrome} + StarterRenderer.php
├── erik/      ErikTheme.php (ThemeModule impl) + Shell + Renderer facade → Sections/{Index, Hero, ArticleView, Cards, Widgets, Controls, Support} + Chrome/   (er-*, --er-* tokens, own erik Vite entry)
├── moonshine/ MoonshineTheme.php (ThemeModule impl) + Chrome/{Chrome,Nav,LocaleSwitcher,Controls,Scripts} + Sections/{Hero, BlogIndex, Article, Cards, Widgets, Controls, Support}   (ms-*, --m-* tokens)
├── magazine/  MagazineTheme.php (ThemeModule impl) + Chrome/{Chrome,Nav,Controls} + Sections/{Home, Taxonomy, ArticleView, Cards, Index, Support, Widgets}   (mag-*, --mag-* tokens, own magazine Vite entry)
├── basic/     BasicTheme.php (ThemeModule impl) + Chrome/{Nav,FooterNav,LocaleSwitcher,ThemeToggle,UserLink} + Sections/{Support,Hero,BlogIndex,Widgets,Chrome} + BasicRenderer.php   (ba-*, --ba-* tokens — a CARICATURE of starter: same design, different prefix, kept wired so the theme factory stays exercised end to end; its src/base/ copy is stamped by bin/generate/stamp-theme-base.mjs, not byte-pinned)
└── jednotka/  JednotkaTheme.php (ThemeModule impl) + Chrome/ + Sections/ + JednotkaRenderer.php   (je-*, --je-* tokens — an INDEPENDENT design, not a prefixed starter: warm paper and ink, hairline rules instead of shadows, a numbered left rail, uppercase mono labels, and a sticky contents `<aside>` beside the article instead of a TOC FAB)
```

Facade `Shell.php`/`Renderer.php` are one-line delegates; markup lives in
`Sections/`, chrome (nav/controls/inline scripts) in `Chrome/`, critical CSS in
`assets/critical/*.css` (concatenated by `InlineCss::files()`), inline script
bodies in `assets/scripts/*.js` (`InlineJs::file()`).

## 2. Admin (`/mark`, admin role) — AdminLayout

`AdminLayout::render()` resolves the `layout` setting: `compact` →
`CompactLayout` (renders `templates/compact.phtml`), otherwise
`templates/layout.phtml`. All actions below call `AdminLayout::render($title,
$content, $activeSection)`.

| Screen | Route | Action | `.phtml` templates |
|--------|-------|--------|--------------------|
| Dashboard | `/mark` | `Cardboard\...\DashboardAction` | `dashboard.phtml`, `dashboard-audit.phtml` |
| Users CRUD | `/mark/users` | `Cardboard\...\UsersAction` | `users-form.phtml` |
| Roles + permissions | `/mark/roles[...]` | `Cardboard\...\RolesAction` | `roles-list.phtml`, `roles-form.phtml`, `roles-permissions.phtml` |
| Settings | `/mark/settings` | `Cardboard\...\SettingsAction` | `settings-form.phtml`, `settings-admin-table.phtml` + `assets/scripts/settings-table.js` (the drag-reorder widget — ONE script wiring every `table[data-nav-table]` from the table's own `data-reorder-url`, so the public nav table, built inline by `SettingsAction::headerNavTable()`, drags exactly like the admin one) |
| Bulk-actions bar | shared partial | `Cardboard\Application\...\BulkActions` | `bulk-actions.phtml` |
| Pages | `/mark/pages[...]` | `Pages\...\PagesIndexAction`, `PagesCreateAction`, `PagesEditAction` | `page-create.phtml` (create + edit; carries `translation:`, the edit slug is editable and renames via `rename()` — alias recorded, page cache flushed; the table shows the per-locale public URL and the pair target) |
| Media manager | `/mark/media[...]` | `Media\...\MediaIndexAction`, `MediaUploadAction`, `MediaEditAction` | `media-list.phtml`, `media-grid.phtml`, `media-bulkbar.phtml`, `media-folders.phtml` (the folder overview — `MediaIcons::folder()`), `media-edit.phtml`, `media-edit-inline.phtml`, `media-upload-form.phtml`, `media-upload-provider.phtml`, `media-picker.phtml`, `media-picker-target.phtml`, `select-all-script.phtml` |
| Cloudinary library | `/mark/media/cloudinary[...]` | `Media\...\MediaCloudinaryAction` (GET, folder navigation + `?root=1` account root), `MediaCloudinaryImportAction` (POST) | `media-cloudinary.phtml`, `media-cloudinary-card.phtml`, `media-folders.phtml` (shared folder tiles) |
| Articles editor | `/mark/articles[...]` | `Blog\...\ArticlesIndexAction`, `ArticlesCreateAction`, `ArticlesEditAction`, `TagsManageAction`, `CategoriesManageAction` | `article-create.phtml`, `article-form.phtml` |
| Locales | `/mark/locales` | `Locales\...\LocalesAction` | `locales-list.phtml`, `locales-edit.phtml` |
| Audit log | `/mark/audit` | `Audit\...\AuditAction` | — (markup inline in the class, `m-*` helpers) |
| Forms editor + inbox | `/mark/forms[...]` | `Forms\...\FormsIndexAction`, `FormEditorAction` (create AND edit — one action, so the two can never render different fields), `FormDeleteAction`, `FormPublishToggleAction`, `FormSubmissionsAction`, `FormSubmissionsCsvAction`, `FormSubmissionDeleteAction` | `form-editor.phtml`, `submissions.phtml` (row deletes confirm via `data-confirm` + the admin shell's `document`-delegated submit listener — HTMX replaces the rows a per-node handler would bind to, and the question never depends on HTMX being loaded) |
| Comments moderation | `/mark/comments` | `Comments\...\CommentsAdminAction` | — (markup inline in the class) |

Admin inline scripts live next to the templates:
`src/Modules/*/Interfaces/HTTP/assets/scripts/*.js` (`admin-shell.js`,
`admin-theme-init.js`, …).

## 3. Auth — AuthTemplate

Self-contained card layout (own inline CSS, `--auth-*` tokens, no module
templates). All four actions are under `src/Modules/Users/Interfaces/HTTP/Actions/Auth/`:

| Screen | Route | Action |
|--------|-------|--------|
| Login | `/login` | `LoginAction` |
| Registration | `/register` | `RegisterAction` |
| Password reset request | `/forgot-password` | `PasswordResetRequestAction` |
| Password reset | `/reset-password` | `PasswordResetAction` |

## 4. Debug (dev only, `APP_DEBUG=true`)

| Surface | Renderer | Markup |
|---------|----------|--------|
| `/debug` panel | `Debug\...\DebugAction` | `templates/debug-page.phtml`, `debug-panel.phtml`, `debug-request.phtml`, `debug-route.phtml` |
| Floating debugbar | `DebugbarMiddleware` (kernel, last) | inline HTML injected into HTML responses; dark-only, theme-independent (no `data-theme` hook — a reader's colour-mode toggle must not repaint it); the brand chip (`nativa-debugbar-brand`) minimizes the toolbar to itself and restores it, the `Panel` button expands the detail panel |

## 5. Error pages

`Core\...\ErrorPageRenderer::response()` — used by the `Kernel` (404/405/500) and
by not-found branches in `ServeBlogImageAction`, `ServeUploadedFileAction`,
`BlogTagsAction`, `BlogCategoriesAction`, `AuthorProfileAction`,
`BlogArticleAction`. Renders through `FrontendLayout` (`noindex`) with a bare
HTML fallback if the layout itself throws.

## 6. Non-HTML surfaces (no templates)

`SitemapAction` (`/sitemap.xml`), `RobotsAction` (`/robots.txt`), `BlogFeedAction`
(`/blog/feed.atom`, `/blog/feed.xml`), `/mark/media/json` (picker endpoint) —
raw XML/text/JSON built in the action classes.

## Rules of thumb

- New admin screen → `.phtml` under the owning module's
  `Interfaces/HTTP/templates/` + `ViewRenderer::render()` + `AdminLayout` shell.
- New public surface → a new `ThemeModule` method implemented in every wired
  theme (`Sections/` classes) + `FrontendLayout::render()` in the action.
  `DesignBlockVocabularyTest` fails until `docs/design-blocks.md`'s surface map
  names the new method too.
- Inline `<script>` body → `assets/scripts/*.js` + `InlineJs::file()`, never a
  heredoc (template hygiene guard).
- Paths in code → `AppPaths::instance()->join()`, never `dirname(__DIR__, N)`.
