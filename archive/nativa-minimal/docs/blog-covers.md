# Blog covers — CoverGenerator

Covers are generated by `Modules\Blog\Application\Services\CoverGenerator`
(CLI: `php bin/cms generate-images`). Everything about a cover is
**deterministic**: the same article always renders a byte-identical SVG — no
timestamps, sorted file discovery, purely positional extraction rules.

## Identity rules

1. **Explicit flags win** — `--template`/`--color` override everything.
2. **Series identity** — front matter `series:` hashes to one shared
   (template, palette) pair for all its members; `series-part:` adds the
   badge ("DIEL N" / "PART N") and the ghost part number.
3. **Slug-hash fallback** — without a series, the slug hashes to its own
   stable identity (table: code/blue, grid/green, rust/orange, wave/purple,
   circuit/cyan).
4. **Version stamp** — front matter `version:` renders as a release mark in
   the bottom-right of the title bar. **LTS releases** (published, even
   non-zero MINOR per `docs/blog-voice.md` → 1.2.0, 1.4.0 …) carry the
   accent ink and an explicit `· LTS` label; dev versions and 0.x drafts
   stay muted. Render-only: the version never enters the identity hash —
   a bump changes the stamp and nothing else (contract-tested in
   `CoverDeterminismTest::testVersionBumpChangesOnlyTheStamp`).

## Code as evidence

A cover can carry a code-evidence element: a terminal window with a snippet
extracted from the article's own body. Selection precedence:

1. `cover-code:` front-matter override (may abbreviate — keep it honest),
2. the first ```diff fenced block (preferred: added/removed lines are the
   strongest proof),
3. the first fenced code block,
4. no code → pattern-only cover.

Snippet: at most `--code-lines` rows (default 5), each hard-truncated to
68 chars, HTML-escaped (like every user value). Diff rows get green/red
tints; other rows stay muted monochrome.

**Provenance contract** — `tests/Unit/CoverCodeIsFromArticleTest.php`: every
auto-extracted snippet line must be literally contained in the article body,
and the shipped disk SVG must match the article it sits next to. An override
is exempt by design (documented SHOULD).

## Cover policy (resolution order)

`resolveCover()` resolves in a fixed order — and explicit front matter is
**reserved for unique editorial images** (real uploads, screenshots):

1. `image:` front matter — unique, deliberately chosen art only, and
   always a root-relative local image (`/storage/…`). Never pin a
   cloudinary URL — a pool URL freezes a resolver output as content and an
   upload under `nativa-media/` is a content image, not a cover
   (`CoverPinPolicyTest` rejects both) — and never point it at the
   generator's own output (`/storage/blog-images/{slug}.svg`) — the
   resolution chain already covers it, and a pin bypasses cache-busting.
2. Local generated SVG — the default for
   articles without an explicit `image:`. Two locations: the flat
   `storage/blog-images/{slug}.svg` (unique slugs) and, when **both locales
   share the same slug**, the locale-qualified
   `storage/blog-images/{locale}/{slug}.svg` — the flat file of an ambiguous
   slug can only ever hold one locale's identity (the generator writes both
   locales' covers to the same path otherwise, and the last one wins).
   every article, with the `?v=` content-hash cache-buster.
3. Cloudinary pool fallback — deterministic per slug, for articles without
   a generated cover.

Enforced by `CoverPinPolicyTest`: every explicit pin must render under the
CSP `img-src` allowlist, must never point at the generator's own output,
and must never be a cloudinary URL (pool URLs are frozen resolver output;
`nativa-media/` uploads are content images — a cloudinary-hosted
screenshot belongs in the article body).

## Cache-busting

Generated covers are served with `Cache-Control: max-age=31536000,
immutable`, so regeneration must change the URL: `resolveCover()` appends
`?v=<8 hex of md5>` to local SVG URLs. The `image:` front-matter field keeps
the plain URL — the query param is added at render time and always matches
the file's current hash.

## Front matter reference

```yaml
---
title: "Rust a Lekalo pre deti ... diel 11"
series: "Rust & Lekalo"     # optional — shared series identity
series-part: 11             # optional — badge + ghost number
version: 1.2.0              # optional — release stamp (LTS = even non-zero MINOR, accent ink)
cover-code: "line one"      # optional — snippet override (use sparingly)
image: "https://…"          # reserved for UNIQUE editorial images only —
                            # never a pool URL or the generated SVG path
---
```

## CLI

```bash
php bin/cms generate-images                          # all articles, auto identity
php bin/cms generate-images --slug my-article        # one article
php bin/cms generate-images --slug my-article --template rust --color orange
php bin/cms generate-images --code-lines 3           # shorter snippets (0 = off)
```

Note: `--template`/`--color` without `--slug` re-themes **every** article —
for series work pass `--slug` per member, or rely on the auto identity.

## Where each cover goes

`CoverPathResolver` (Application layer, not the CLI shell) owns two
decisions, and `CoverPathResolverTest` pins both:

- **the locale** of an article comes from the content directory through
  `ContentServices::mapper()` — the family root is the configured
  `settings.locale`, every other locale is a `{lang}` subdirectory. Nothing
  hardcodes `sk`/`en`; a third locale works the day the mapper knows it.
- **the path**: flat `blog-images/{slug}.svg` for a slug one locale owns, and
  `blog-images/{locale}/{slug}.svg` for a slug two locales share.

These used to be private methods of the command, which is how the collision
check could compare `sk_SK` against `sk`, never match, and write every cover
in the repository locale-qualified. Re-run `bin/cms generate-images` after any
change to an article's `version:` — the version stamp is part of the bytes, so
a bump without a regeneration leaves the stamp behind.
